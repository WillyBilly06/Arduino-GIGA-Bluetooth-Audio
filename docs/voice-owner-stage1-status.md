# Optional voice control owner - stage 1

This source stage starts from dev.13 and is included in experimental dev.14 with an actual optional PSM3 consumer in OwnedHost. The component-only build evidence below predates the combined dev.14 package; see [package validation](validation/dev14-2026-10-27.md) for the current build. It is not full HFP/HSP support and is not an audio-continuity fix. No firmware from this branch has been flashed.

`OwnedHostConfig::voice_control` borrows a caller-reserved `VoiceProfiles` object through `end()`; `voice_config` selects separate HF and HS RFCOMM listener channels. All access belongs to the serialized actor. The default pointer is null, so default PSM3 refusal, service UUIDs and SDP records remain unchanged. This stage shares the existing A2DP-enabled Classic actor; voice-only operation is not admitted yet. No Arduino public voice or microphone registration facade is exposed.

The owner connects the existing actual RFCOMM/HF/HS code to secure L2CAP admission, one mux per Classic peer, complete-frame copied output, two receive frames per DLC, segmented AT rows, expiration and channel/ACL teardown. It returns a receive credit only after the control parser consumes that frame. Protocol output can wait in a separate durable FIFO while the shared control queue is busy; already committed output progresses even when optional new AT work is held behind older input. Uncertain AT/RFCOMM timeout retires the actual channel. A scoped queue and ordered adapter-mailbox fence prevents old-CID output from entering a replacement. Voice-only close signaling can wait in the existing copied control FIFO while independent A2DP media proceeds. No ACL credit is fabricated or live partial SDU canceled.

Root executed all actual post-fix portable CPU cases: owned host/default refusal/retirement/media/LE736checks, standalone voice owner339checks, existing Classic combined861checks and both AVRCP queued/partial retirement cases, each return0. The dedicated local-close case first failed on the previous source because early matching disconnect completion bypassed the old queue/mailbox fence. The fix retains a peer-qualified CID tombstone after local close, keeps it across parser-capacity retries, and admits replacement only after the scoped queue and ordered mailbox drain. These are synthetic Android ARM64 CPU results; they do not establish controller routing, actual M7 voice operation or phone interoperability.

The next required stages remain: honest HF/HS SDP record construction/registration; real H4 SCO dispatch, synchronous event/handle/storage/flow/deadline ownership; exact stock-controller voice routing; CVSD PCM and mSBC/H2 receive/transmit; voice worker/I2S arbitration; public microphone-provider registration that the worker actually calls, with serialized detach fencing and fresh epochs; then Root's actual target/phone/duplex validation. No phone call has been made by this source lane.

Primary-source research retains the CYW43xxx SCO-over-HCI route as unknown. BTstack's [chipset support notes](https://github.com/bluekitchen/btstack/blob/master/chipset/README.md) describe flow-control limitations, and [HCI initialization](https://github.com/bluekitchen/btstack/blob/master/src/hci.c) demonstrates a Broadcom transport-selection command. Linux's [Broadcom driver](https://github.com/torvalds/linux/blob/master/drivers/bluetooth/btbcm.c) reads/writes PCM interface parameters. Those sources do not establish support or values for this board's exact HCD. No routing VSC or ROM write is included.

The supplied Apache-2.0 Broadcom SBC encoder includes mSBC mode, and the retained OI decoder already supports it. The encoder is not imported here: its `long`-based SINT32 typedef, global analysis history and optional ESP32 allocator path require a fixed-width, per-instance lazy port first. This observation is unrelated to the current LHDC playback shortage diagnosis.
