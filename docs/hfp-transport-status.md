# HF/HS transport status and integration boundary

New standalone modules implement protocol logic only. Both profiles remain disabled and unadvertised: no integration file, scan UUID, SDP record, call action or hardware route is changed here. Full HFP/HSP is unfinished until synchronous audio, controller feasibility, public lifetime and actual interoperability are completed.

## Source gap map at published dev12 basis

- ClassicProfiles.cpp channelOpened accepts PSM1,0x19,0x17; there is no PSM3 mux owner or AG RFCOMM channel discovery.
- RadioProtocol.h already frames H4 SCO and bth_packet.c decodes its handle/status. OwnedHost receive dispatch has no SCO consumer.
- bth_links.c admits Classic ACL link type1; related synchronous requests need a separate matching-ACL owner and generation, not reuse of ACL data handles.
- GAP currently enables ACL-only controller-to-host flow. Its nominal synchronous Host Buffer Size is not a functioning SCO pool. Synchronous flow, buffer ownership and connection-event masks must be decided while disconnected.

## Primary sources consulted

- [RFCOMM1.2, adopted SIG doc263754](https://www.bluetooth.org/docman/handlers/DownloadDoc.ashx?doc_id=263754), sections4..6. It adapts [ETSI TS101369 V6.3.0](https://www.etsi.org/deliver/etsi_ts/101300_101399/101369/06.03.00_60/ts_101369v060300p.pdf). Implementation is independently written; no stack implementation copied. One frame per L2CAP SDU; separate frame/MCC C/R; credit field excludes length; bilateral MSC precedes data. Legacy aggregate/MSC FC remains required. SCN1..30; negotiated credit mode is a mux characteristic. New-DLC SABM uses60s timeout, within its60..300s range. This is a bounded module, not conformance qualification.
- [HFP1.8, adopted SIG doc489628](https://www.bluetooth.org/DocMan/handlers/DownloadDoc.ashx?doc_id=489628), sections4.2/4.11/4.29/4.34: HF SLC uses feature exchange, conditional codec list, discovered indicator order/status and event enablement. Three-way/HF-indicator features stay unset; their optional procedures are not advertised. Codec selection is separate from SCO establishment. CVSD is mandatory; mSBC requires its real voice backend. Gain0..15 is distinct from AVRCP volume.
- [HSP1.2, adopted SIG doc158743](https://www.bluetooth.org/DocMan/handlers/DownloadDoc.ashx?doc_id=158743), sections4.3..4.8: HS reports button/RING and optional gains. CKPD is AG/state dependent, so no unconditional answer semantic is invented.
- [Infineon CYW4343W Rev.J](https://www.infineon.com/assets/row/public/documents/non-assigned/49/infineon-cyw4334wkubgt-datasheet-en.pdf), sections8/10 describe family synchronous/PCM capability; the exact stock-HCD HCI voice route remains unknown. No VSC, pin reroute or firmware modification is inferred. Arduino [GIGA schematic](https://docs.arduino.cc/resources/schematics/ABX00063-schematics.pdf) does not establish a populated microphone or usable PCM-to-H7 audio route.

## Required owner hooks (not installed)

1. Reserve one authenticated/encrypted Classic owner plus L2CAP PSM3 channel before initializing bth_rfcomm_t with a nonzero fresh generation. A peer-pair has one mux. Reject duplicate crossed L2CAP admission rather than create two muxes. Channel RX MTU must cover max information+6; core max512. The mux has two DLC slots. No callback borrows its input past receive.
2. Reserve durable control output and bounded application RX storage BEFORE receive/next/send. A successful encode is a durable-queue commit, not an HCI completion. An OutputFull retry must reuse the same state/input. Credit window is<=7; owner reserves window*N1 storage per DLC and returns one credit only after consumption. Legacy mode requires owner backpressure via MSC FC or disconnect before accepting unbounded traffic. Any outstanding PN/SABM/MSC/DISC timeout invalidates the entire mux; the outer owner must close L2CAP before initializing a fresh generation. Receive and time-bearing output operations service expiration before accepting a late response or replacement transaction. Core parsing never implies a security decision. Input and output spans must be disjoint. A refused local DLC remains refused until DISC/session reset. PN N1 below23 is refused. Initial flow-mode negotiation is serialized; no crossed-PN winner is invented.
3. Route RFCOMM DATA for a ready matching DLC to HfpControl or HspControl. next() produces one AT row only after a durable owner TX reservation is available. If negotiated N1 is smaller than an AT row, preserve a bounded copied row and cursor and fragment the byte stream; do not call next twice to reconstruct it. The local5s response deadline includes durable-queue delay and does not prove bytes reached HCI/the peer. Caller time is monotonic uint32 milliseconds, intervals<half range. Release resets control/audio epochs; stale-generation input/commands cannot revive them. No automatic dial/button/reconnect. Every AT response timeout makes the HF/HS control session terminal; do not reuse the RFCOMM stream for a new untagged transaction. Receive checks expiration before consuming a response.
4. Only enable mSBC feature after real encoder/decoder, H2 framing and synchronous route are ready. HfpAudio defines separate VoiceCodec/PCM/provider contracts. No microphone means explicit silence mode, with separate no-mic and active-provider-starvation counters; no ADC/I2S input is opened implicitly. Detach is single voice-owner serialized and must fence old callbacks before caller destroys context. A strictly increasing provider epoch preserves microphone-fault/no-mic counters within the same audio generation, including across detach; only a new audio generation resets them.
5. SCO integration needs matching synchronous request/complete/change/disconnect events, independent handle and generation, packet-status loss handling, real controller buffer/readback/flow policy, TX deadlines and bounded pools. A negotiated codec, command status or sync handle is not proof of PCM delivery or acoustic output. I2S arbitration must release A2DP ownership before voice changes rate and restore it with a fresh epoch.

## Validation status

Fixtures are portable and have no radio or call effects. Root observed missing-module RED, then executed the final standalone RFCOMM/HF/HS/PCM fixtures as Android ARM64 CPU cases with return0. Official M7 objects and the full CM7 Receiver compile/link include these modules. Live host integration, controller feasibility, transport interoperability and call audio remain absent or unverified. No phone call was performed by this source task.

Bounded current control subset: baseline HF basic call commands, seven discovered AG indicators, remote gains, and optional codec negotiation. Three-way calling, CLI/call-waiting notifications, HF indicators, voice recognition and enhanced call controls are not advertised. One configured incoming server channel per mux is supported (HF/HS selection is an outer-owner policy); two total DLC slots are bounded. These limits must be reconciled with any future SDP/feature matrix before enablement.
