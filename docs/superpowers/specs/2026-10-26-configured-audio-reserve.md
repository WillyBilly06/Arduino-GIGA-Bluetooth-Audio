# Configuration-driven real-PCM reserve

The receiver must fill a real audio reserve before starting its constant-rate I2S output. Decode can run ahead into bounded storage; DMA consumes at the selected rate with the existing slow PLL2 drift correction. Codec changes allocate only the selected queue, assembler, one decoded block and PCM ring. This is the user's approved buffer-scaling work; no additional permission gate is introduced.

Use actually decoded stereo PCM frames as startup readiness, not RTP timestamp guesses, transport-fragment counts, or allocated byte capacity. Let H be the existing approximately 1 ms, four-frame-aligned DMA half. P is the total real PCM watermark before priming, including the 2H frames subsequently transferred to DMA. Require 2H <= P <= R, where R is ring capacity. After priming, publish the actual queued/prepared counts; pushing a decoder block can overshoot the minimum watermark. Do not claim an exact startup delay.

Automatic base startup targets in milliseconds: SBC 50, AAC-LC 50, HE-AACv1 40, aptX 60, aptX HD 55, LDAC 50, LHDC V5 60, Opus 40. Raise the selected target to at least ceil(decoded-block-frames * 1000 / output-rate) + 12 ms. Automatic ring capacity is target + 10 ms. Allow 2..320 ms ring capacities so accepted low-rate HE decoder modes are not silently dropped; those modes can exceed the separate 200 ms total phone-to-DAC requirement and remain unqualified. All advertised/common modes fit below 100 ms receiver PCM capacity. This engineering policy is not a measured jitter or latency guarantee.

Zero global buffer fields select configuration-aware defaults. Nonzero codec overrides take precedence over nonzero globals. An explicit startup_packets setting selects the existing compressed-packet startup path and legacy prime/recovery threshold. Otherwise startup_buffer_ms selects the actual PCM watermark. Reject an explicit ring too small for the selected real-PCM watermark; never silently start underfilled or on a full compressed queue. Existing explicit manual profiles remain available.

Automatic maximum SDU size is 2048 bytes, matching the advertised media receive MTU; maximum AU remains 8192. Queue slots use ceil(120 ms / decoded block duration) + 4 as a capacity hint, bounded to 8..64 before the allocation target. Cap automatic queue allocation to floor(65536 / (maximum_packet_bytes + 2)) slots, with at least one slot for an explicitly larger legal packet. Explicit queue capacities are never silently capped. Capacity is not permission to accumulate that amount of audio time or an exact packet-duration model. Fragments may be drained/assembled/decoded before playback because PCM readiness independently gates DMA.

Keep the existing DMA cadence, IRQ/mask/cache/PLL policy and raw clock-result accounting. Preserve all original 44/full/active and cumulative whole-20-us gates. The latest measured clock gate remains FAIL 4/91, maximum 22.545833 us. No new I2S phase admission, controller command or SDRAM initialization is included. Stock Arduino SDRAM initialization uses PLL2R; it must not be enabled blindly against the current exclusive PLL2 audio owner.

The default allocator is shared by Fast and Dma categories. Check actual allocation/headroom at high rates; do not count DMA completion as physical output. The existing A-D-P inventory already includes the ring plus unsent decoded scratch, so do not add the ring a second time. Headphones are directly connected to the user's PCM5102A; the exact impedance remains pending. Analog load and audible continuity require separate verification.

Decoder work is bounded to available packets. A dequeued fragment, NeedMoreData or corrupt packet counts as work; a genuinely idle/no-startup-progress turn ends the burst. The host must be notified after every processOne return, including idle, and final mailbox drain/lifecycle epoch checks remain intact.
