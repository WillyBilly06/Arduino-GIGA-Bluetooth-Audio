# Clock execution lane: design consultation only

After comparing the minimal synchronous ceiling seriously against the exact pinned SDK, recommend a private, bounded experiment using the EXISTING higher-priority host thread for the hardware call, with controller computation/normal ACK on the decoder. This is conditionally viable; it is not a standalone async call or a20us guarantee. Lifecycle cancellation must be an explicit terminal outcome rather than an ACK into a reset controller. No implementation, new API, priority, heap/thread, mask, kernel-lock, busy-wait, backend or gate change is proposed here.

## Four choices

| Choice | Benefit to test | Cost / unresolved issue | Recommendation |
|---|---|---|---|
| Existing host lane, after radioPoll and outside radio_mutex | Existing priority32 cannot preempt itself with the host work seen in the old decoder lane; radio gets its normal poll first | Needs explicit result/ACK/cancellation protocol; host owns backend for its full existing span; higher IRQs/timers/callers still expand it | First bounded candidate, subject to invariants below |
| Dedicated higher-priority clock thread | Separates executor from radio callbacks; can outrank default host | New thread/stack/heap/events/join lifecycle/role coverage; codec ownership still needed; still not IRQ-proof; priority choice changes radio scheduling | Defer; extra machinery without a proved need |
| Temporary owned decoder24→33→owned24 only around backend | Smallest source change; synchronous lifecycle/result/ACK remains intact, no mailbox/thread/heap; hardware IRQ0/6 and backend remain unchanged | Exact pinned RTX setter overwrites both effective/base and does NOT recompute PI. It can discard an already waiting host32 inheritance or lower a legitimate higher inherited priority | Naive held-mutex variant is blocked by actual semantics; constrained outside-lock/proven-no-waiter variant is NOT approved or a solution for the current public thread-safe lifecycle |
| Fixed I2S clock plus ASRC | Removes fractional-PLL transition from tracking | New sample domains, filter/history/buffers, ratio acceptance and quality/CPU/group-delay evidence; existing decoded−discarded−prepared inventory cannot mix source and output frame units | Separate substantial design, unimplemented; no fidelity/E2E claim |

A separate thread at the SAME effective priority is not a justified avoidance mechanism. The proposed host lane uses the existing higher-priority actor and correct post-unlock release point; it is not an absolute timing proof.

## Minimal ceiling: actual pinned API proof, not an assumed preference

The promotion option is attractive on cost: roughly one narrow scope around the existing backend call, no asynchronous slot/ACK/lifecycle machinery, no new thread/heap, and no changed hardware interrupt priorities or backend registers. Calls before/after all original DWT/read sites would preserve the measured whole-backend interval; host32 would briefly wait while decoder33 executes. That potential advantage was assessed directly rather than discarded because the original sketch preferred a host lane. Normal call duration is not a guaranteed8us: higher IRQ/timer/user work can still extend it, and priority-setting SVC/internal-critical latency occurs outside the old measurement but still matters to radio service.

A constrained ceiling outside all relevant mutex ownership, or under a proved no-waiter context, could be a different design. Existing host-lane execution avoids dynamic priority rewrites, at the explicit ownership/accounting complexity detailed below. ## Proposed one-slot ownership

One POD request/result slot under codec_mutex, containing copied decision(stream/output/serial/requested/lower/upper), observation time, state, raw ClockTrimResult and terminal reason. No PCM pointers, queue, allocation or extra thread. Atomic pending_hint is only an optimization for QUEUED work; mutex-protected slot state is authoritative. No second decision overwrites QUEUED, EXECUTING or DONE. "Coalesced" means one pending wake/slot, NOT replacing a controller's unacknowledged decision.

1. Decoder FIRST consumes DONE/CANCELED before the1ms observation gate. Only then may it call observe. While QUEUED/EXECUTING is outstanding, do not call observe and accidentally clear internal pending. Existing inventory/error bookkeeping may continue; invalid eligibility can cancel QUEUED while decoder owns the mutex, with the original negative-ACK/suspension semantics. No catch-up decisions or changed1s/500/10 policy.
2. A new decision fills QUEUED and stores pending_hint with release ordering. Do NOT signal the higher-priority host while processOne still holds codec_mutex. decoderMain585–590 must signal host_events AFTER EACH processOne returns/destructs its lock, including early returns, before the next of64 iterations. The existing1ms host fallback may also service during an existing UnlockDuringWait; the same mutex protects it. Wake once/coalesce; never self-spin on failed lock.
3. Host always performs normal radioPoll FIRST. After the radio lock scope ends, if hinted, TryLock(codec_mutex) once. Failure leaves QUEUED/hint untouched and continues the normal wait/RX cadence; no waiting on codec/queue/event mutex, no user callback, radio poll recursion or radio lock reacquisition inside this service. Any prerequisite unavailable nonblockingly defers/cancels rather than blocking radio. Default mutex/priority inheritance policy is not changed.
4. Under that lock, revalidate running/playing/configured/clockEnabled/eligible, exact stream and output epoch, current initialized/running I2S sample-rate/ownership/backend state and decision identity. Preserve the existing250ms controller stale-sample restriction: an older queued decision is canceled without hardware rather than silently executing across that suspension boundary; do not reuse the harness20s source-age limit. This is conservative eligibility, not a widened actuator budget. Stop/config cannot interleave an apply because they require the same mutex. end may request shutdown during an in-flight call, but i2sEnd remains after worker quiescence; do not interrupt the unchanged backend halfway through a hardware transition.
5. Move private schedulerPrepare to IMMEDIATELY BEFORE the actual host i2sClockTrim, using the copied decision key. Enqueue/cancel must not prepare an observer capture: current prepared_valid would otherwise poison the next request. The existing i2sClockTrim/I2sClockTrimState::apply remains intact: same seven ownership snapshots, DWT endpoints/readback/masks/whole20us check/CUM validity. No subtracting preemption, shifting endpoints or treating host execution as an IRQ-free span.
6. Host stores the actual result and records clockWitness ONCE under the same lock BEFORE publishing DONE; it must not call observe/acknowledge or update PI state. This prevents an intervening lifecycle reset from discarding an executed timing/overrun result. Keep CUM on actual backend results; a canceled-before-call decision is not a fabricated Unchanged/zero-duration result. Publish raw backend fields with applied_valid=false until worker ACK reconciles control; do not claim the old integral value is the newly accepted trim. Clear pending_hint while STILL holding codec_mutex after publishing DONE or CANCELED; only then release the lock and coalescent-wake decoder using its existing semaphore. Clearing the hint after unlocking could erase a new request published by the worker.
7. Decoder consumes one matching DONE exactly once, applies existing epoch/partial/readback/fault handling and acknowledge validation, updates accepted quantized PI state and public clock snapshot, then frees the slot. Preserve the current rejected-ACK fallback/fault semantics326–327: one result/terminal successful ACK consumer, not an invented promise that the existing failure path makes only one function-call attempt. A duplicate/stale DONE must never trigger hardware, a new-controller ACK or another CUM increment.

Only the host service may execute a queued hardware request; only decoder normal completion consumes/ACKs it. Memory boundedness does not imply a finite service deadline: caller-held mutexes/codec work/radio callbacks/IRQs may defer it. Original controller stale-gap policy must remain visible rather than extending bounds until success.

## Lifecycle and no-lost-outcome rule

Before clockStop resets control, retire QUEUED as CANCELED_BEFORE_EXECUTION and clear hint. Preserve DONE (and its raw result/witnessed marker) as EXECUTED_EPOCH_RETIRED; never overwrite it in clockBegin. A later decoder step consumes that terminal old-generation slot BEFORE observing a new epoch, without ACKing the new controller. Do not wait for the lower-priority worker while holding codec_mutex or radio_mutex. New decisions wait until that one terminal slot is consumed; this is bounded backpressure, not a result queue.

This is a necessary semantic distinction: **every issued decision has one terminal ACK or explicit lifecycle cancellation/retirement; not every canceled decision receives an ACK after its controller is destroyed.** If a literal successful ACK for every issued decision is required, the preferred constraints are incompatible with existing synchronous host lifecycle resets: either lifecycle completion must be deferred or ACK ownership must be expanded. Neither alteration is silently assumed here. Preserve per-begin terminal accounting so cancellation is not lost/refused/accepted fiction; raw executed results remain distinguishable from never-executed cancellations. No new public API/log framework is specified.

Decoder exit needs a mutex-protected final drain/cancel after its main loop. EXECUTING cannot be inspected concurrently because host holds the mutex; after acquiring it, exit sees DONE or QUEUED. If DONE/current epoch still exists, consume using normal worker ACK/fault handling; if already retired, consume terminal bookkeeping without a new-controller ACK. QUEUED is canceled. Existing end's host-then-decoder join order plus this finalizer must leave slotEMPTY/hintfalse before i2sEnd, Impl deletion or begin reuse. Partial-begin failure with no decoder has no issued decision; never invent an ACK. configure/stop/end must call the same private retirement rule before reset/release, and must not drop a DONE merely because running becamefalse.

Foreground stats/diagnostics take the existing mutex and observe only coherent published snapshots; they never ACK or execute. Once hardware has changed but control ACK is pending, applied_valid must not falsely present the old PI value as current accepted hardware. No extra user callback under locks. Existing radio→codec lifecycle ordering is retained; the host service is strictly codec-only outside radio ownership, and decoder still never takes radio_mutex. All-codec/BLE/HF+HS/latency goals remain intact; this prototype makes no completion/fidelity/acoustic/physical200ms claim.
