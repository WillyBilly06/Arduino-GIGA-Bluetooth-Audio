# Owned HF/HS control and synchronous voice integration

The user requested normal Bluetooth audio profiles and a pluggable microphone input, with explicit None when no microphone is fitted. Existing A2DP/BLE playback and all codec/configuration memory policies must remain intact. Root owns all hardware, ADB and actual execution of Android CPU fixtures. This source lane uses the already approved project scope and does not publish or flash.

The implementation is staged because the exact CYW4343W stock-HCD synchronous route is not established. Stage1 connects the existing real RFCOMM/HF/HS protocols to OwnedHost through an opt-in, caller-reserved VoiceProfiles object. Default construction has no active voice storage or PSM3 registration. The actor exclusively calls its attach/receive/poll/close methods; the application must retain the object through end(). Two distinct listener channels allow HF and HS on one mux. Durable bounded protocol output is reserved before receive/next; a copied AT row survives N1 fragmentation. Each received frame owns storage until consumption, and only then returns a credit. Untagged timeout closes the actual L2CAP channel. Channel replacement waits for the old scoped queue and ordered UART mailbox to drain. No arbitrary queue/ACL-credit reset is permitted.

Stage1 remains unadvertised. SDP HF/HS record construction is separate from registration; no feature/backend claim is inferred from protocol source. It must not expose an inert public microphone API or claim SCO audio. Subsequent stages add an actual synchronous owner tied to the authenticated/encrypted ACL peer, standard HCI request/completion/disconnect validation, independent SCO storage/flow/deadlines and H4 dispatch, then CVSD PCM and verified mSBC/H2 codecs. Public microphone registration belongs only to the actual voice worker that calls it, with serialized detach fencing and fresh epochs. I2S admission must arbitrate A2DP/voice ownership and restore a fresh output epoch; no output clock change may happen in the radio receive callback.

Primary constraints: no guessed VSC/ROM/HCD writes; no borrowed RX or microphone callbacks after lifetime retirement; no automatic phone call action; no synthetic HCI credits; no A2DP/BLE backend changes unrelated to voice. Firmware build, portable CPU assertions, controller routing, phone interoperability and acoustic output are distinct evidence.

BTstack's chipset table marks CYW43xxx SCO-over-HCI unknown, and its chipset notes describe Broadcom/Cypress SCO transmit-flow limitations. These are reasons to retain the controller route as unknown, not evidence that this exact board cannot support it: https://github.com/bluekitchen/btstack/blob/master/chipset/README.md . CYW4343W UART/PCM family capabilities alone do not qualify the stock patch route: https://www.infineon.com/part/CYW4343W .
