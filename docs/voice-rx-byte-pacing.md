# Experimental fallback byte-conservation stage

Root first executed the unchanged strict fixture against the old source: unfragmented/NCP controls returned0 with3840bytes; fragmented CVSD and mSBC aborted with1920 versus3840expected bytes. This change repairs that opt-in source accounting. It is not complete physical pacing or a hardware voice qualification.

Fallback entitlement now uses HOST payload bytes. Accepted HCI RX length contributes once, including known-length error/zero-filled audio. A zero-length event contributes zero; no air-length conversion fabricates microphone progress. The selected CVSD pipeline rejects odd payloads explicitly in this fallback because it consumes complete S16 samples. Standard NCP operation and ACL/LE pools are unchanged.

The budget debits the exact prepared ticket byte count only after local H4 copy admission. Duplicate, stale or forged receipts cannot debit again or change worker cursor/progress. Adapter receipts bind the unit ticket and byte count. Microphone demand follows committed60-byte unit progress, preserving sub-unit remainders, rather than rounding incoming packets. One initial worker unit is retained as before; worker retirement contention keeps the exact receipt without retransmitting H4.

Stored local entitlement is different from controller queued lead or credits. Its bound is RX-pool storage plus59bytes of worst codec-unit residual:315bytes for4×64. RX48+48 may therefore retain96, spend60 and carry36; RX64 may carry bytes across a unit boundary. No accepted bytes are silently clipped. Overflow returns an explicit capacity error, increments dedicated rx_pacing_overflows/rx_pacing_rejected_bytes state counters and causes the adapter to retire voice. Those internal counters are not yet new public VoiceStatus fields; public diagnostic wiring remains separate work.

Tests cover TX20/30/40, mSBC22, RX30+30/TX60, steady48 and64, burst carry, zero/error/invalid shape, explicit overflow, duplicate/forged tickets, queue-retirement Busy, close/reopen generations, reverse Host NCP counts and unchanged reported-NCP behavior. Stale tests here mean old tickets/generations after retirement; automatic wall-time budget expiry is not implemented.

Remaining gates are explicit: monotonic microsecond clock/phase/freshness contract; separating eligible stored bytes from instantaneous controller queue capacity; stale partial-mSBC handling; actual route/FIFO/packet shape and no-overrun tests; long-call drift and legacy SCO's valid zero geometry. The fallback stays disabled unless explicitly opted in. Existing one-H4-submission owner passes bound work but do not prove real-time controller capacity. These remaining requirements cannot be closed by a CPU byte-count test or by rejecting all fragmented operation.
