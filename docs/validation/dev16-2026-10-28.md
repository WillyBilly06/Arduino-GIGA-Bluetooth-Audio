# Dev.16 validation - experimental development source

The AAC fix addresses a reproduced diagnostic ADTS frontend defect: when one complete frame was followed by a partial frame, a later retry could decode the completed prefix again. The frontend now retains only the undecoded suffix in the same bounded assembly and keeps its remaining work estimate. Decoder arithmetic and non-AAC paths are unchanged. Normal Raw/LATM A2DP AAC consumption differs from diagnostic ADTS; this test does not demonstrate the same failure in negotiated phone audio and does not explain the separate LHDC shortages.

The actual old-source CPU fixture reproduced the defect: the prefix trace was 1,1,2 and totals reached 3072 rather than 2048 frames. The corrected source passed 11/11 real-decoder/frontend cases. The strengthened unchanged-source run also asserts 100 retained bytes and Q16=13212 after the first prefix, then zero retained bytes and zero Q16 after completion. Timestamp/sequence changes, reset, consumed input, bounded capacity, real overflow, malformed/error recovery and ownership checks passed. The owned two-frame synthetic ADTS provenance is distributed in [the fixture notice](../../tests/fixtures/owned_adts_retained_prefix.md); no external media is included. These CPU tests use fake radio and I2S, not a phone or GIGA audio output.

The initial existing-regression batch is preserved as failed evidence: `media_retained` passed 35 checks and `clock_frontend` aborted with exit 134 at `invalid_backend_ack`. The identical original fixture also aborted on the published 4851 baseline. Baseline and candidate debug states agreed: one decision, zero hardware trims and one pending host-mailbox entry. The fake test thread did not service the asynchronous host mailbox. The minimal test-only correction drives the real host/completion steps outside the codec mutex and adds positive issue/execution/trim assertions while retaining all prior assertions. The corrected fixture was executed on both baseline and candidate: each passed 394 checks. The six cases skipped by the first batch passed separately: five output-wait/lifecycle modes and receiver lifetime (349 checks). All owned jobs/processes were confirmed quiet. The corrected fixture preserves the original failed records and confirms the missing fake-host service step. This is a harness correction, not a physical clock defect or audio/clock repair; no full-suite or sanitizer PASS is claimed.

The focused independent static review established no introduced Critical or Important defect. Its initial recommendation to assert intermediate Q16 state was addressed by the strengthened CPU run. Review and finite fixtures are bounded evidence, not proof over all AAC/HE-AAC streams or concurrency schedules.

The exact corrected production source passed separate official Arduino Mbed GIGA 4.6.0 Cortex-M7 Receiver and VoiceQualification builds and static link audits. Each compiled 191 library translation units in 223 compile rows with seven enabled codec defaults, six linked decoder-operation families, project-owned host, default 2 Mbaud UART, private observers disabled and the stock 139-command HCD. Both builds exited 0 with all owned jobs quiescent. Compiler stack records are not runtime stack watermarks. Image hashes and sizes are in [the machine-readable summary](dev16-2026-10-28.json).

The compiled snapshot carried the preceding library version/paragraph metadata. The final version changes those two property values and documentation; every production source/example byte is checked against the compiled snapshot. The final ZIP is not separately compiled, and its checksum remains in an external sidecar. The source and test updates have not been deployed or tested with phone audio.

A separate actual M7 decoder-only diagnostic used the earlier public-fc7 codec basis, rather than this combined AAC/voice candidate. All 28 vector safety cases passed, with 26 strict numerical matches and two QUALITY_UNQUALIFIED LHDC nonzero comparisons. Both LHDC passes produced full S32 CRC dbdf4256 against unchanged ARM64 differential CRC fe87f2ef; all 16 frame CRCs differed. The sparse 224-points/channel comparison observed 158 left and 156 right differences, maxima 192 and 160 S32 counts. These are sparse maxima, not full-stream maxima; independent LHDC fidelity remains UNKNOWN. No low bits, CRCs, expected values or thresholds were relaxed. Eight zero/lifecycle cases passed and 328 provider allocations/frees balanced; no radio, I2S or acoustics were exercised. The saved full application was restored after that diagnostic. Neither restoration nor these numeric checks deployed the dev.16 AAC fix.

No fix-image deployment or phone audio test is claimed. Existing LHDC long-playback shortages remain unresolved; voice routing, real calls, microphone hardware, long calls, physical output, acoustics and 200 ms total phone-to-DAC latency remain unqualified. All existing codec/default/notice boundaries remain; this candidate is not stable.
