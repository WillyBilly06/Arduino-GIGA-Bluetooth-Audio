# Current unreleased local source: October 29

This page describes the local combined source after the dev.17 release snapshot. It is experimental and has not been deployed or field-qualified as this combined source. The [published dev.17 ZIP](../../README.md#install-and-start) remains the earlier version; this page does not announce a new release or assert that the published ZIP contains these changes.

The combined 406 source passed a full synthetic native runner in normal and ASan+UBSan modes: each recorded 191 compiles, 125 project runtimes and eight child suites. Its default Arduino Mbed GIGA 4.6.0 Cortex-M7 Receiver linked and passed a static audit. Its unflashed BIN SHA-256 is `d837e4b346941c371b0602c7bb71ac1271d403e719c28d249b50f19345458883` (551,104 bytes). Those results are software and build evidence; they do not establish a phone call, real-time safety, acoustic quality, continuous playback or an underrun cause. The local documentation overlay itself is not part of that frozen build input.

The source adds Generic Attribute Service Changed with a volatile, unbonded-client CCCD; service handles 14–17 replace the previous empty service at handle 6. Vendor RX, TX and notification handles remain 9, 11 and 12. A host-owner-only description mutator publishes the affected vendor-service range for an enabled current connection. Trusted LE bonding, persistent change state, Database Hash and Robust Caching are not implemented. Previous-client cache migration and phone interoperability remain untested.

HF/HS remain disabled by default and require an available, qualified backend. A received gain-command rejection after an established HF service-level connection is recorded separately from SLC state; it does not establish call audio. The legacy `allow_rx_pacing` field remains for source compatibility but is ignored. RX-derived credits cannot establish controller TX retirement, so the current HCI SCO backend requires verified synchronous completion flow. In the earlier separate voice diagnostic, the supported-command bit for enabling that flow was clear, flow readback was off and setup ended unavailable; no enabling write or call audio was established. This is historical diagnostic evidence, not a live status query of the current receiver.

The SBC/mSBC and AAC source includes narrowly defined integer-arithmetic changes. Their selected host tests preserve the recorded comparison outputs, but finite comparisons do not establish codec conformance or physical audio quality. The shared clock controller now retires its old frames-per-packet estimate and cohort on unhealthy suspension or a long observation gap, then learns from fresh healthy packet/frame deltas. Valid zero-output completions remain in the packet denominator; the last acknowledged trim and cumulative counters are retained. The exact compressed-duration ledger remains future work, and retained data may cross a fault. The nominal codec rate and applied trim are not an absolute sender-rate or I2S wire measurement. Backend timing guards and masks are unchanged.

**Workspace-only evidence:** detailed source/test/build receipts for this local candidate are retained in the task workspace under `build/dev406-adaptive-evidence` and its referenced dev391, dev394, dev397, dev404 and dev405 evidence directories. Those directories are not included in an ordinary copied library package. The historical validation pages retain their original observations and mark links that point outside the library. Missing local receipts must be treated as unavailable evidence, not a pass.
