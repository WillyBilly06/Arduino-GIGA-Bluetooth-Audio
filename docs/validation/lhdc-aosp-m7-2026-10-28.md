# Corrected LHDC decoder: actual GIGA Cortex-M7 test

The corrected source ran on the physical GIGA, USB UID
`003C00393533510934353531`. Eight AOSP encoder configurations at
44.1/48/96/192 kHz and 16/24 bits each completed two passes of 32 stereo
frames: 512 decode calls and 245760 decoded frames in total.

All 16 case passes met the safety, repeatability and sampled-input fidelity
gates. There was no decode-time allocation/free, output-guard damage,
concealment, tracked-memory drift or observed deadline miss. The counted
providers made 216 allocations and 216 frees, ending with zero live blocks or
raw bytes. Full S32 frame CRCs and whole-output CRCs repeated within each
configuration; these are repeatability checks, not equality to another CPU.

The longest measured call was 1691 us at 480 MHz, below the corresponding
5000 us audio-unit duration. This is isolated decoder timing with no radio or
I2S application linked. It does not establish streaming scheduling behavior.

The source-independent reference is the encoder's original synthetic PCM,
aligned using the known analysis/synthesis sample delay. Each pass scores
432 samples per channel per configuration across frames 5 through 31. The
fixed limits are absolute level error <=0.1 dB and signal/error >=20 dB.
The maximum reported sampled level error was 0.021 dB; the minimum sampled
signal/error ratio was 25.832 dB. These sparse results complement the earlier
full-stream host measurements; they do not replace full-stream target scoring
or prove all-content codec fidelity.

The diagnostic selected LHDC only, leaving the source's production codec
defaults unchanged. Requested codec memory varied with the active rate:
12024 bytes at 44.1/48 kHz, 22888 at 96 kHz and 42632 at 192 kHz, for either
tested depth. Both passes reopened with identical footprints. Other codec
families have their separate build/native/earlier target evidence.

The installed diagnostic was 387540 bytes, SHA-256
`9c4b801a918608a65be07933dafcc077849e7dca5e0854a8653fbee9dfd93e32`.
Its complete readback matched. All 16 encoded/reference arrays were checked
against read-only ELF/BIN bytes before execution, and all 424 production source
files matched the corrected source snapshot.

After capture, the complete saved 786432-byte M7 application region was
restored and independently compared byte for byte. Its SHA-256 is
`079c1df4c7276c425397a4725a2265dde78523dde0a136ab93b7107c6295a09f`;
the original receiver prefix remains `ad1d2f5e...`. All nine phone codec fields
were independently verified, owned YouTube playback resumed, and fresh real
PCM/DMA progress was observed. The original logger resumed as serial epoch 9
with ten settled control writes; the temporary helper was removed.

The production Receiver application with this correction remains undeployed.
This experiment does not establish an underrun fix, physical audio quality,
phone-to-DAC latency, all-profile interoperability or exact M7/ARM64 numerical
parity. See the adjacent JSON for source bindings, measurements and local
receipts. Earlier failed differential evidence is retained unchanged.
